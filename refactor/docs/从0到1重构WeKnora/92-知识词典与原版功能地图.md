## 1. 先把项目想成一家资料室

用户把资料交给资料室，资料室整理、分类，再根据问题找到相关片段，交给模型组织回答。网页负责让用户操作，后端负责执行规则，数据库负责记住发生过什么。

```text
用户点击上传
  → 前端发送文件
  → 后端检查身份和知识库权限
  → 保存文件，建立解析任务
  → 提取文字，切分片段，计算向量
  → 用户提问时检索相关片段
  → 模型依据片段回答，页面逐步展示答案和引用
```

第一轮只打通这条链路，之后继续补齐原版功能。打通主链路意味着“有了能工作的第一版”，不意味着“已经完整复刻”。

| 学到这里 | 当下只需要理解 | 对应阶段 |
| --- | --- | --- |
| 网页能打开 | 组件、路由、样式、开发服务器 | `S1` |
| 数据能保存 | 请求、响应、数据库、事务 | `S2` |
| 用户能登录 | 令牌、租户、权限 | `S3` |
| 能配置模型并建库 | 表单、状态、增删改查 | `S4–S5` |
| 文件变成可搜索资料 | 上传、任务、解析、分块、向量 | `S6–S7` |
| 回答逐字出现 | 流式传输、取消、引用、消息持久化 | `S8` |
| 产品功能逐项一致 | 智能体、工具、组织、渠道、自动化等 | `S9` |
| 别人能稳定使用 | 部署、恢复、监控和完整验收 | `S10` |

## 2. 第一层：把页面画出来

### 2.1 组件：把一个界面分成几块

`Vue` 组件可以理解为一个有外观、有数据、有行为的界面零件。知识库卡片是组件，整个知识库列表页也可以是组件。`.vue` 文件中，`template` 描述显示什么，`script` 描述数据和行为，`style` 描述样式。

先读 `frontend/src/main.ts` 看应用怎样启动，再读 `frontend/src/App.vue` 和 `frontend/src/views/platform/index.vue` 看外壳。第一次不必追完里面的全部功能。

**练习：** 在新工程画一个知识库卡片，接收名称，点击时向父组件报告选择结果。能解释“父组件传数据、子组件发事件”即可继续，不要第一天把所有卡片都抽成通用组件。

### 2.2 路由：网址与页面的对应表

`Vue Router` 决定访问某个网址时显示什么页面。刷新详情页后还能回到同一份知识库，靠的是网址里保存了知识库标识，而不是上一页的临时变量。

原版入口为 `frontend/src/router/index.ts`。注意几个容易照旧文写错的地方：

- `/register` 复用登录组件处理邀请注册，不是独立的另一套表单。
- `/platform/settings` 打开平台外壳中的设置弹窗；路由本身使用空出口，不能再挂载一份设置组件。
- `/platform/knowledge-search` 是兼容重定向，会打开全局命令面板；不能因为旧文提到“搜索页”，就以独立新页面代替原版交互。
- `/embed/…` 使用独立入口，不属于主应用路由树。

**练习：** 从列表打开详情，再直接刷新详情网址。列表、详情、返回和刷新均正常才算路由通过。

### 2.3 样式：组件库负责控件，工具类负责布局

`TDesign` 提供按钮、输入框、弹窗等现成控件；`Tailwind CSS` 把常见样式变成可以直接写在模板上的类名。两者可以一起使用。用工具类写排列和间距，可以减少手写样式，但不会自动得到原版外观。

本轮目标布局方案是 `tailwindcss: ^4.3.3`；安装与版本核验以[前端指南](91-Vue与Tailwind前端开发手册.md)为准，不表示原版已经使用或新工程已经安装。

保持原版外观时，优先保留这些事实来源：

| 内容 | 原版入口 | 学习时怎么用 |
| --- | --- | --- |
| 组件库与样式加载顺序 | `frontend/src/main.ts` | 保留组件行为，检查全局样式覆盖顺序 |
| 颜色、字体、圆角、阴影 | `frontend/src/assets/theme/theme.css` | 使用原版变量，不凭感觉换一套颜色 |
| 组件细节覆盖 | `frontend/src/assets/theme/tdesign-overrides.less` | 先保留所需覆盖，再逐页判断能否简化 |
| 明暗主题 | `frontend/src/composables/useTheme.ts` | 原版使用根元素的 `theme-mode` 属性 |
| 字体偏好 | `frontend/src/composables/useFont.ts` | 字体变化会影响行高和换行 |
| 图片与图标 | `frontend/src/assets/img/`、`frontend/src/components/icons/` | 复用原素材并保留许可信息 |

**练习：** 对同一张知识库卡片，在相同窗口尺寸下对比原版与新工程的浅色、深色截图。检查文字换行、间距、圆角和悬停状态。不要只比较背景颜色。

### 2.4 状态：页面现在记着什么

`ref` 保存组件自己的变化，例如搜索框文字。`computed` 根据已有数据算出结果，例如筛选后的列表。`Pinia` 保存跨页面共享的数据，例如当前用户和当前租户。

原版入口为 `frontend/src/stores/auth.ts`、`frontend/src/stores/organization.ts`、`frontend/src/stores/knowledge.ts`。不是每个输入框都要放进全局仓库；只在当前弹窗使用的数据留在组件里就好。

**练习：** 在顶部显示当前用户，退出后顶部和页面权限同时变化。再刷新网页，观察哪些数据来自本地存储、哪些重新向后端获取。

## 3. 第二层：让页面与后端说同一种话

### 3.1 接口契约：双方约好的表格

`API` 是前后端交换信息的入口。契约不仅是网址，还包括请求方法、字段名称、响应结构、状态码、分页和失败含义。前端显示正常，并不代表契约就正确。

原版请求基础设施在 `frontend/src/utils/request.ts`；具体业务接口在 `frontend/src/api/`。学习时沿着一条线读：页面按钮 → 对应接口函数 → 请求封装 → 后端路由。

**练习：** 创建一次知识库，在浏览器网络面板记下实际请求和响应，隐藏凭据后写入契约记录。新后端应实现这个契约，不能因为用 `Python` 就擅自重命名字段。

### 3.2 令牌刷新：门票过期后只换一次

访问令牌证明当前请求是谁发的。令牌过期后，如果页面同时发出多个请求，不应各自刷新一次；它们应等待同一次刷新，再使用新令牌重试。退出后，尚未返回的旧刷新结果也不能把用户重新登录进去。

原版共享刷新逻辑在 `frontend/src/utils/authRefresh.ts`，普通请求和聊天流都会用它。读代码时关注 `refreshAccessTokenShared()` 和会话代际校验。

**练习：** 模拟多个请求同时返回 `401`，确认只发生一次刷新；刷新失败后回到登录页，没有无限重试。再测试“刷新还未完成时退出”。

### 3.3 租户：同一栋楼里的不同资料室

租户用来划分数据归属。当前登录用户、用户默认租户和当前选择的租户不是同一个概念。前端切换了租户名称，不代表后端权限已经正确。

查看 `frontend/src/stores/auth.ts`、`frontend/src/stores/organization.ts` 和请求层的 `X-Tenant-ID`。后端必须验证成员关系，不能相信客户端随意传来的租户标识。

**练习：** 两个租户各建一份不同名称的资料，反复切换并刷新；界面不串数据，直接用另一租户资源标识请求也会被后端拒绝。

### 3.4 能力与权限：有没有这个功能、你能不能用

部署能力表示后端是否提供某项功能；角色权限表示这个用户能执行哪些操作。服务健康又是另一件事：有功能，也有权限，仍可能因为服务故障而失败。

入口为 `frontend/src/config/deploymentCapabilities.ts`、`frontend/src/config/settingsAccess.ts` 和 `frontend/src/config/toolbox.ts`。路由守卫和按钮隐藏只是界面提示，真正的授权必须在后端执行。

**练习：** 对同一页分别用管理员和普通成员访问，并直接调用受保护接口。不能把“按钮隐藏了”当作权限测试通过。

### 3.5 版本化缓存：旧快递不能覆盖新快递

缓存是暂存已经取过的数据；版本号用于判断哪次请求还有效。例如编辑知识库后取到了新名称，早先较慢的请求才返回时，不能再把旧名称覆盖回来。

原版入口为 `frontend/src/stores/resourceCache.ts` 和 `frontend/src/stores/versionedRequest.ts`。先能正确刷新数据，再处理重复请求和并发覆盖，不要一开始设计复杂缓存系统。

**练习：** 人为延迟第一次列表请求，让第二次请求先返回；最后页面必须显示第二次结果。租户切换后旧请求也不能写进新租户页面。

## 4. 第三层：理解文档、检索与流式聊天

### 4.1 上传完成，不代表资料已经能搜索

上传只是把文件传给后端。解析是提取内容；分块是把长文切成片段；向量化是把片段转换成便于比较相似度的数字。每一步都可能失败，因此页面需要分别显示进度和结果。

入口为 `frontend/src/stores/uploadQueue.ts`、`frontend/src/stores/uploadTasks.ts`、`frontend/src/stores/uploadTasksCore.ts` 和 `frontend/src/components/knowledge-processing-timeline.vue`。

**练习：** 上传一个正常文件和一个解析失败文件；离开再返回列表，状态仍正确。测试取消和重试后不会出现重复文档。具体状态值照原版接口，不自行发明另一套外部协议。

### 4.2 检索增强问答：先找证据，再组织答案

`Embedding` 是把文字转换成向量；关键词检索找字面相关内容，向量检索找语义相关内容；`Rerank` 对候选结果进一步排序。`RAG` 把检索结果作为上下文交给模型，让回答能够附上来源。

查看 `frontend/src/api/retrieval.ts`、`frontend/src/api/knowledge-base/index.ts`、`frontend/src/components/GlobalCommandPalette.vue`。前端不负责实现检索算法，但要正确传递范围、展示结果并打开来源。

**练习：** 在固定文档里写入一个明确答案，提问后核对检索片段、引用文档和最终回答。检索没有结果时，页面应如实展示，不能伪造引用。

### 4.3 流式传输：一篇回答分多次送来

`SSE` 允许后端持续发送事件。网络收到的一块数据不一定是一条完整事件，所以不能把每个网络块直接当成完整消息解析。

原版传输入口是 `frontend/src/api/chat/streame.ts`，事件类型看 `frontend/src/api/chat/streamTypes.ts`，界面处理看 `frontend/src/composables/useChatStreamHandler.ts`。文件名确实是 `streame.ts`，查源码时不要改成自己猜测的名称。

**练习：** 先用确定性的假回答观察增量展示，再做停止生成、断网、重试和切换会话。开始新回答后，旧请求的迟到事件不得混进新回答。外部事件名、结构和顺序以原版契约为准。

### 4.4 富文本：好看与安全要一起做

模型可能返回 `Markdown`、代码、公式、图表和图片。`marked` 负责解析，`highlight.js` 负责代码高亮，`KaTeX` 负责公式，`Mermaid` 负责图表，`DOMPurify` 负责清理危险内容。把模型文本直接放入 `v-html` 不安全。

查看 `frontend/src/utils/security.ts`、`frontend/src/directives/stableHtml.ts` 和 `frontend/src/components/ProtectedResourcePreview.vue`。稳定渲染还要避免每收到一小段文字就重建整块内容，导致图片闪烁、图表丢失或滚动跳动。

**练习：** 用普通段落、代码块、公式、图表、超长文本和恶意标签各测一次；再测试无权限图片与失效资源。安全清理不能因为“先做演示”而省略。

## 5. 第四层：把主闭环扩展成原版产品

### 5.1 智能体、工具和审批

`Agent` 可以理解为会决定下一步操作的助手；工具是它能调用的具体能力；`MCP` 是连接外部工具服务的一种协议。能输出工具名字不代表工具真的执行成功，审批被拒绝也必须阻止执行。

入口为 `frontend/src/views/agent/`、`frontend/src/api/agent/`、`frontend/src/views/settings/McpSettings.vue`、`frontend/src/api/mcp-service.ts`。先复刻配置和一次调用，再补齐多步执行、错误、审批、取消、子任务和原版事件展示。

**练习：** 分别同意、拒绝、取消一次有副作用的工具操作；核对后端实际结果，不能只看提示文案。

### 5.2 嵌入与渠道：别人网页里的聊天窗口

嵌入页在另一网站中运行，不能直接借用管理后台的登录凭据。宿主通信还要校验来源。即时通信渠道则要处理外部平台的身份和消息，二者不是同一种接入。

入口为 `frontend/embed.html`、`frontend/src/embed-main.ts`、`frontend/src/views/embed/`、`frontend/src/composables/useEmbedBridge.ts` 和 `frontend/public/weknora-widget.js`；渠道配置还涉及 `frontend/src/components/IMChannelPanel.vue`。

**练习：** 在独立宿主页打开嵌入聊天；验证允许来源、拒绝来源、凭据过期、历史会话和引用访问。主应用退出或切换租户不应让访客获得额外权限。

### 5.3 国际化与主题：不同状态也要像原版

国际化不是最后把中文替换成英文；它影响日期、错误提示、组件库语言和布局。主题也不只有背景颜色，弹窗、菜单、代码块、禁用态都要一致。

查看 `frontend/src/i18n/index.ts`、`frontend/src/i18n/locales/`、`frontend/src/i18n/localeKeyAudit.ts`。每做一页就沿用翻译键，最终逐语言检查溢出、漏译和控件文案。

**练习：** 同一页面切换语言和明暗主题，刷新后偏好仍正确；长文案不遮住按钮，弹出层与页面主题一致。

## 7. 怎样证明“功能和样式一样”

先在 `S0` 记录原版提交号和部署模式。不同版本、角色、租户、功能开关看到的界面可能不同；把它们混在一起，永远无法判断是否一致。

每实现一个操作，就追加一行记录。下面是模板，填写时把“待记录”换成真实证据：

| 功能与操作 | 原版版本／角色／配置 | 原版行为和截图 | 新版页面／接口 | 功能验收 | 视觉验收 | 差异与下一步 |
| --- | --- | --- | --- | --- | --- | --- |
| 知识库：空列表 | 待记录 | 待记录 | 待实现 | 未验收 | 未验收 | 待核对 |
| 知识库：创建失败 | 待记录 | 待记录 | 待实现 | 未验收 | 未验收 | 待核对 |
| 聊天：生成中取消 | 待记录 | 待记录 | 待实现 | 未验收 | 未验收 | 待核对 |
| 设置：深色弹窗 | 待记录 | 待记录 | 待实现 | 未验收 | 未验收 | 待核对 |

功能对照时，除了正常路径，还要检查空数据、加载中、失败、无权限、重复提交、刷新、取消和恢复。视觉对照固定浏览器、窗口、缩放、字体、数据和主题；检查布局尺寸、文案、图标、交互状态、滚动和响应式表现。

`Web` 验收不能替代桌面验收。原版还存在 `Wails` 相关运行时代码，例如 `frontend/src/wailsjs/`，以及对外命令行等入口。先完成浏览器版可以作为里程碑；若目标包含整产品一致，桌面本地能力、启动恢复和外部客户端也要单列实现与测试，不能以浏览器通过宣称全部完成。

## 8. 卡住时从哪里读起

| 看到的问题 | 优先查的地方 | 暂时不用读什么 |
| --- | --- | --- |
| 页面空白 | 控制台、`frontend/src/main.ts`、路由、组件导入 | 向量检索与智能体 |
| 页面有了但按钮没反应 | 事件绑定、加载状态、对应 `api` 函数 | 全部状态仓库 |
| 请求返回 `401` | 请求头、`authRefresh.ts`、登录状态 | 样式和分块逻辑 |
| 切租户后出现旧数据 | `organization.ts`、缓存失效、迟到响应 | 图表渲染 |
| 上传成功但搜不到 | 任务状态、分块、向量、检索范围 | 聊天气泡样式 |
| 回答混入上一次内容 | `streame.ts`、取消、请求代际、会话标识 | 模型列表布局 |
| 原版与新版看着不同 | 主题变量、字体、组件库覆盖、工具类和样式层叠 | 后端数据库 |
| 本地正常、部署后失败 | 代理、静态路径、入口回退、流式与连接配置 | 重写业务逻辑 |

每次只追一个具体操作：哪个按钮触发了哪个请求，后端返回了什么，哪份状态改变了，页面为何重画。能把这条因果链讲清楚，再进入下一阶段。

## 9. 本文的核对边界

本次整理静态核对了原版入口、路由、依赖、主题、主要页面、接口目录和关键基础设施文件；删除了容易过期的文件数量统计，以及与完整复刻目标不符的“最小迁移包”路线。

未据此宣称新工程已经存在，也未执行产品运行、全量接口、视觉或桌面验收。最终完成度必须来自第七节的实际记录，而不是本文列出了多少功能。
