# `S9`：把问答闭环补齐成完整的 `WeKnora`

[返回目录](./00-目录.md) · [上一章：会话与流式问答](./10-S8-会话与流式问答.md) · [下一章：部署与全量验收](./12-S10-部署与全量验收.md)

细化学习顺序见[14 全链路 60 步实践路线](./14-全链路60步实践路线.md)的步骤 `41–58`，每步映射回本章任务，配套原理阅读、可见产物与理解检查。

## 1. 这一阶段要做成什么

前面已经让一份文档经过上传、解析、检索，最终变成带引用的回答。现在要把原版剩余能力一项项补回来。每个模块都要真实处理数据；只有页面、假数据和成功提示，还不能算完成。

本阶段实际记录保存在本目录的 `实践记录/S9/`，由[进度与验收记录](./13-进度与验收记录.md)统一登记；按九组任务保存原版操作、新版结果、测试和截图证据。

本章严格沿用[总路线](./01-总路线与学习方法.md)的九组顺序。每组可以学习多天；每天只选一个有输入、有输出、能验收的小任务。不要同时写智能体、沙箱和自动化。

**开始条件：** `S8` 的正常问答、持久化、停止、断流与权限检查已经通过；原版版本、部署模式和功能清单已在 `S0` 固定。没有运行环境的功能标记“待验证”，不能从范围表里删掉。

**路径约定：** 源码链接指原版；下面的目标文件均是建议新建或扩展的文件。`B/` 表示 `refactor/python/backend/`，`F/` 表示 `refactor/python/frontend/`，不是实际要创建的缩写目录。

## 2. 每个功能都按这六步做

```mermaid
flowchart LR
    A[原版操作与契约] --> B[数据与权限]
    B --> C[业务与接口]
    C --> D[页面与状态]
    D --> E[失败及恢复测试]
    E --> F[功能和截图对照]
```

1. 在原版中实际操作，记录入口、参数、状态、成功与失败响应。先查前端调用，再查后端路由。
2. 确认原版数据关系、唯一约束、删除影响与访问范围。复用已有表，不凭页面猜一套新结构。
3. 先写一个服务级用例，让真实记录能增删改查；业务在服务，持久化在仓储，路由只处理协议和身份依赖。
4. 使用原版 `TDesign` 控件、主题和素材，布局用 `Tailwind CSS ^4.3.3`；先接真实查询，再接修改和刷新。
5. 至少主动制造一次失败，检查错误反馈、重试、权限、迟到响应与数据一致性。
6. 固定角色、主题、语言、字体和窗口尺寸对照截图，把证据写进[进度与验收记录](./13-进度与验收记录.md)。

测试文件按领域放入 `B/tests/unit/`、`B/tests/contract/`、`B/tests/e2e/`；前端状态与组件测试放在对应模块，关键浏览器流程进入新工程的端到端测试目录。不要为每一行包装代码写镜像测试，优先覆盖用户会遇到的风险。

## 3. `S9.1`：知识管理全量

### 3.1 先理解这些功能怎样相连

标签提供横向分类，文件夹提供树形位置，`FAQ` 保存明确的问题与答案，`Wiki` 把多份资料组织为可浏览的知识页面，图谱展示实体和关系。它们共享资料来源，但不能用同一种删除和更新规则处理。

原版入口：[知识库组件](../../../frontend/src/views/knowledge/components/)、[Wiki 页面](../../../frontend/src/views/knowledge/wiki/)、[知识路由](../../../internal/router/routes_knowledge.go)、[图谱路由](../../../internal/router/routes_graph.go)。

| 目标位置 | 本组职责 |
| --- | --- |
| `B/app/services/knowledge_bases.py` | 扩展标签、文件夹和批量操作编排 |
| `B/app/services/faq.py`、`wiki.py` | 条目、页面、来源和版本规则 |
| `B/app/repositories/` | 原版关联、版本、目录与权限查询 |
| `F/src/views/knowledge/` | 列表、目录树、条目编辑及知识页面 |
| `F/src/api/knowledge-base/`、`wiki/` | 保留原版参数和响应 |

### 3.2 按顺序动手

1. **标签：** 先记录创建、重命名、删除和批量关联的接口；实现同知识库内的合法性检查；页面完成选择、筛选和移除。检查删除标签后文档仍在，计数与筛选结果及时更新。
2. **文件夹：** 读取原版树结构与移动规则，先实现列树，再实现创建、改名、移动和删除。阻止把节点移入自身或后代；移动后刷新，确认目录和文档归属一致。
3. **批量操作：** 明确跨页选择、全选、已删除条目和部分失败的语义；后端逐项检查权限，前端展示实际结果。测试“选中后另一个用户删除其中一项”，不要把剩余成功项全部显示失败或全部显示成功。
4. **手工知识与 `FAQ`：** 从一条问答的创建、查询、修改、删除开始；再加入标签、批量编辑、导入导出。导入先验证字段与错误行，再按原版规则提交，不能把无法解析的文件当作空导入成功。
5. **`FAQ` 检索：** 用固定问题核对命中规则、答案正文与引用；确认其特殊优先策略不会把普通文档错误当成标准答案。
6. **`Wiki` 阅读：** 先显示目录、页面、来源和反向链接；源文档删除后，按原版规则处理失效来源，不能留下可绕过权限的正文。
7. **`Wiki` 编辑和版本：** 实现更新、历史查看与回滚；核对原版并发编辑的版本检查和错误响应。两人编辑同一页时，让后保存的一方看到冲突，不能静默覆盖。
8. **`Wiki` 自动整理：** 再接摄取待办、批处理与知识库级收敛；重跑相同任务不重复制造页面。任务成功不等于所有来源已处理，进度要反映实际范围。
9. **图谱：** 先实现节点、关系和证据读取，再实现原版配置与更新流程；点击关系能回到证据块，查询和证据访问都校验知识库权限。

**输入与结果：** 在一个知识库里准备两份资料、两个标签和两个文件夹，完成移动、筛选、生成知识页面及来源跳转；刷新后所有关系保持正确。

**退出检查：** 批量部分失败可见；树无循环；版本冲突不丢内容；来源撤销有效；`FAQ/Wiki` 和普通文档的权限边界一致。然后继续资料来源与预览。

### 3.3 从“给一份文档贴标签”开始落代码

先只处理一个库、一份文档和一个标签。输入是可信身份、知识库标识、文档标识及标签标识；输出是保存后的真实关联。字段名用本组原版样例替换，不能把下面的描述当新协议。

1. 在 `B/app/repositories/` 对应知识仓储增加读取标签及文档所属库的查询；先用两条测试记录证明它们确实属于同一允许范围。
2. 在 `knowledge_bases.py` 的关联操作中先授权，再验证标签与文档关系，最后调用仓储写关联。关联重复提交如何处理，以原版唯一约束和响应为准。
3. 服务划定事务，仓储只执行查询与写入；写关联失败时，测试再次读取文档，确认正文没有被误删。
4. 在原知识路由对应的目标路由接这个服务，沿用请求模式和响应外壳。先用接口测试完成关联与读取，暂时不接批量按钮。
5. 在 `F/src/api/knowledge-base/` 增加对应调用，再给文档行接一个原版标签选择控件。提交中禁用重复动作，失败保留原选择，成功重新读取关联。
6. 最后实现删标签：清理标签和关联后重新查文档、块和索引，确认资料仍存在。此时才扩展多选与逐项失败展示。

接下来把同样的“身份与关联”思路用于文件夹，但新增移动前的祖先检查；树上的父子关系不能只靠前端拖动位置决定。

`FAQ` 先保存一组问题与答案，再验证检索结果使用哪个字段；`Wiki` 先读页面与来源，再添加版本条件更新。版本条件更新是“只有仍为我读到的版本才保存”，不能先无条件覆盖再检测冲突。自动整理待办必须在派发任务前或与业务写入协调保存，重复消费后再查页面数量和来源集合。

**停下来检查：** 标签显示了却刷新丢失，先查关联事务是否提交；删除标签后文档消失，查删除条件与级联配置；`Wiki` 冲突未提示，查更新条件是否包含原版版本信息。每种功能都要有自己的真实数据检查，不能用标签测试替代整组。

## 4. `S9.2`：文档来源与完整预览

### 4.1 先把入口变多，不要复制多套摄取流程

网页、外部数据源、手工正文和文件上传，最终都应该进入已验证的文档处理链路。来源负责取得材料，后续保存、解析、分块和索引复用 `S6` 能力。

原版入口：[数据源设置](../../../frontend/src/views/knowledge/settings/DataSourceSettings.vue)、[数据源接口](../../../frontend/src/api/datasource/)、[原文预览](../../../frontend/src/components/document-preview.vue)、[图片设置](../../../frontend/src/views/knowledge/ImagePipelineSettings.vue)、[DocReader](../../../docreader/)。

目标位置：`B/app/integrations/datasources/`、`B/app/services/datasource_sync.py`、既有摄取服务，以及 `F/src/views/knowledge/settings/` 和预览组件。解析器、存储与向量库配置分别扩展对应领域，不放进一个万能设置服务。

### 4.2 从一种来源、一种格式开始

1. **网页抓取：** 核对原版链接输入与抓取结果结构，限制协议和访问范围；对每次重定向重新校验目标。正常网页、超时和受限制地址都应得到明确结果。
2. **数据源配置：** 先复刻连接表单和连接测试，保存脱敏配置；读请求不返回凭据。连接测试成功不意味着同步已完成，两种状态分开显示。
3. **一次同步：** 为一项外部资料记录稳定来源标识，转入摄取流程；再次同步同一材料，按原版规则更新而不是新增重复文档。
4. **增量与删除：** 核对外部改名、内容变化、权限变化和删除如何映射本地；外部请求失败不能误判为“全部资料已删除”。
5. **同步任务：** 补日志、进度、重试与取消；同步期间修改连接配置时，旧任务不得回写新一轮结果。
6. **文本与办公预览：** 按原版支持格式逐个准备固定样本，验证预览、下载、页码或片段定位；保留预览库要求的字体、工作线程与资源文件。
7. **图片与多模态：** 补图库、原图与派生图、图片证据编辑及模型选择；配置开启时才执行相应处理，部分图片失败必须能结束任务并显示实际结果。
8. **解析设置：** 补分块调试、解析器、模型、存储、向量和图谱设置。修改设置不一定自动重建旧索引，按原版交互说明影响并支持相应重解析操作。
9. **完整格式表：** 为基线中的 `PDF`、办公文档、表格、图片、音视频等各留一份测试材料。原版支持但当前没有依赖环境的格式保持“待验证”。

**检查例子：** 正常同步一份外部文档，再撤销访问权限并同步。新页面不能继续通过预览链接绕过当前访问限制。把下载地址给另一租户，也必须被拒绝。

**退出检查：** 来源去重、同步失败、取消、重解析、受保护预览和生产资源路径都有证据；支持格式清单与原版逐项对照。

### 4.3 把“一份外部资料”接到已有摄取服务

同步不是重新实现解析器，而是取得外部材料后，给 `S6` 提供同样可追溯的输入。先选一个已授权的测试来源；外部来源标识用于认出同一份资料，不等于本地文档标识。

1. 在 `B/app/integrations/datasources/` 对应适配器只实现一次读取：输入已授权连接配置和来源标识，输出原版需要的内容、来源元数据或受控资源引用。对超时、拒绝访问和不存在分别保留错误类别。
2. 在来源仓储查“连接范围 + 外部来源标识”的现有关联；查不到才按原版规则创建，查得到则进入更新判断，不能每同步一次都新增文档。
3. 在 `datasource_sync.py` 中保存本次运行身份，再调用既有摄取服务。使用稳定来源关系关联本地文档，并把本轮处理配置交给原有任务入口。
4. 接上同步状态读取接口，页面分别显示连接测试结果和同步运行结果。连接能通，只证明凭据和地址可用，不代表资料已解析。
5. 第一次同步后读取块与索引；第二次同步不变内容，检查记录数和任务行为符合原版；第三次改内容，检查更新后能命中新正文。
6. 将来源服务改为返回超时，再同步。只记录本轮失败，不把未读到的目录当空目录去删除本地全部文档。

预览另外走一条短链：页面请求受保护资源 → 服务校验当前访问权 → 取得原件或派生资源 → 预览组件按格式显示。先验证文本，再验证带页码的 `PDF`；随后补对应工作线程、字体和生产资源路径。

**停下来检查：** 同步有记录却没有块，沿本地文档标识查任务受理；预览白屏但下载成功，查浏览器资源请求和格式适配；撤权后仍能看见正文，查受保护读取和前端缓存，而不只检查来源列表。

## 5. `S9.3`：聊天完整体验与产物库

聊天不只是追加文本。编辑、重试、分支和回退会改变消息与上下文关系；附件和产物又有自己的生命周期。

原版入口：[聊天 API](../../../frontend/src/api/chat/index.ts)、[聊天页面](../../../frontend/src/views/chat/)、[产物页面](../../../frontend/src/views/artifacts/)、[收藏接口](../../../frontend/src/api/user-favorites.ts)。

目标位置：扩展 `B/app/services/chat.py`、会话与消息仓储，增加产物服务；前端扩展 `F/src/views/chat/`、`F/src/views/artifacts/` 和对应接口。

1. **会话管理：** 先补重命名、置顶、收藏、单个与批量删除；核对原版排序及恢复行为，删除当前会话后应回到合理入口。
2. **编辑和重试：** 记录原版是更新原消息、重建后续消息还是开启新分支；沿用实际规则。操作时取消或隔离旧生成，不能把旧流继续写入新答案。
3. **分支与回退：** 先在后端验证消息关系和上下文截点，再接按钮。分支应有可追溯身份，回退不能误删另一分支的内容或文件。
4. **临时附件：** 复刻选择、解析、删除及发送时的引用；附件所属会话与永久知识库资料区分，附件读写都检查当前会话权限。
5. **语音：** 先做录音或音频输入和转写结果展示，再接发送；没有权限、空录音、用户取消和转写超时均有反馈。转写完成不能自动代替用户确认发送，除非原版明确如此。
6. **模型和上下文设置：** 补模型切换、联网搜索、历史范围、推荐问题和消息操作；不同会话的临时输入状态不能串用。
7. **产物：** 先保存模型或工具生成的文件及关联消息，再做列表、预览、下载和删除。文件路径由服务端受控解析，不能接受任意磁盘路径。
8. **引用全量：** 验证页码、图片、表格和块位置；来源被删除或无权访问时保留合理提示，不泄露资源正文。

**成功练习：** 在一轮回答后建立分支，分别继续提问，刷新后两边历史和产物关系仍正确。

**失败练习：** 生成中执行回退，再放行旧流；旧流不能污染回退后的消息。下载另一租户产物应失败。

**退出检查：** 每种消息操作都有持久化和取消测试；原版长消息滚动、复制、代码与附件样式都已比较。

### 5.1 先实现一次有持久化证据的消息分支

这里的分支是历史关系，不是把数组复制一份。先在 `B/app/repositories/messages.py` 及原版对应实体中确认怎样表达分支、前序消息和当前上下文；保留真实结构，不另造一套消息树。

1. 准备已有的两轮测试对话，给每条用户与助手消息标出真实身份，画出原版在选定消息处分支后保留哪些历史。
2. 在 `chat.py` 的对应操作中校验会话与目标消息归属，再按原版规则确定上下文截点。先返回准备使用的消息集合供测试断言，不急着调用模型。
3. 接既有消息仓储保存分支变化；同事务需要变更的关系一起提交。保存失败后重新读历史，确认原分支仍可用。
4. 启动新生成前使旧运行的写回失效或按原版取消。沿用 `S8` 的会话与代际检查，不能仅清空页面数组。
5. 接前端分支按钮，成功后按真实返回身份加载目标历史；刷新页面后，应仍进入正确分支。
6. 在测试中暂停旧流，执行回退，再放行旧流。断言当前正文、引用、运行状态都没有被旧事件覆盖。

附件先做“保存文件与会话关联 → 解析状态可查 → 发送时引用 → 删除后拒绝读取”；产物则做“生成文件 → 关联输出消息 → 受保护下载”。二者都复用资源读取边界，但不能复用错误的生命周期。

**停下来检查：** 分支刷新后消失，查真实关系是否保存；重试后上下文混入另一分支，查消息集合选择；产物下载失败，先区分文件不存在与当前身份无权读取，不把两者改成任意磁盘读取。

## 6. `S9.4`：`Agent`、技能、记忆与工具

智能体在一轮任务中可能多次“决定操作 → 调工具 → 看结果”。普通问答的模型输出只是其中一种步骤；不能只在前端画出工具卡片就认为工具真的运行了。

原版入口：[智能体页面](../../../frontend/src/views/agent/)、[智能体路由](../../../internal/router/routes_agent.go)、[记忆路由](../../../internal/router/routes_memory.go)、[技能设置](../../../frontend/src/views/settings/SkillSettings.vue)。

目标位置：`B/app/agent/` 管运行编排，服务层管配置，仓储管记录；`F/src/views/agent/` 管配置，聊天组件管理执行时间线。继续复用模型网关与流式传输。

1. **配置：** 实现列表、创建、编辑、删除，验证绑定的模型、知识库、技能和工具属于允许范围；先让一个无工具智能体正确回答。
2. **单工具：** 选确定性的只读测试工具，定义输入校验、结果、超时和错误；后端真实执行一次，前端显示开始、结果及最终答案。
3. **多步循环：** 加入迭代上限、时间预算和取消信号；循环中的每步都校验工具权限，模型生成的参数不能跳过验证。
4. **审批：** 在有副作用的操作前保存待审批状态；同意后执行，拒绝、过期和撤销后不执行。重复点击同意不能导致两次写操作。
5. **暂停继续：** 保存足够恢复的运行状态和标识；恢复时重新验证身份与资源权限，不能使用已经被撤销的旧授权。
6. **技能：** 按原版支持的安装、文件读取、更新、启停和卸载流程逐项实现；校验归档路径和文件访问范围，技能声明不能自动赋予系统权限。
7. **记忆：** 区分历史消息与长期记忆，补查询、编辑、删除和作用域；新用户不能读取别人的记忆，删除后新对话不应继续注入已删除内容。
8. **子任务与协作：** 对照原版事件关系实现父子运行、状态展示、取消传播和失败聚合；一个子任务失败是否终止整体，以原版规则为准。
9. **上下文处理：** 核对压缩、历史、工具结果和记忆的组装次序；日志只记录排错必需信息，不记录完整秘密或受保护文档。

**检查矩阵：** 无工具、工具成功、输入无效、超时、拒绝审批、重复审批、运行中撤权、父任务取消，逐项观察真实执行结果。

**退出检查：** 前端时间线与后端运行记录一致，未知事件可诊断，已失败运行不会被后续流收尾覆盖为成功。

### 6.1 把一次工具调用拆成可观察的执行步骤

先只选确定性的只读工具，并用模型替身固定产生一次调用。模型输出“要调用什么”是建议，后端确认“允许调用且参数有效”之后才执行。

1. 在 `B/app/agent/` 已有运行入口接收可信身份、智能体配置和会话标识；服务读取配置并验证关联模型、知识范围及工具权限。
2. 先走无工具回答，复用模型网关、消息保存与 `S8` 流式输出，确认新入口没有形成另一套保存逻辑。
3. 接模型工具请求解析：依据原版协议提取工具身份与参数，校验参数结构，再交给对应适配器；未知工具在执行前明确失败。
4. 调用前记录当前运行与工具调用身份，发布原版开始事件；真实取得结果后保存执行结果，发布完成或失败事件，交回模型继续决定。
5. 每次循环检查取消与预算。达到迭代上限时明确收尾，不能因模型持续要求工具而无限执行。
6. 前端时间线按调用身份更新同一项，结果事件不能重复创建两张卡片；历史加载从持久化记录恢复，而不是只依赖实时事件。

审批接在执行之前：先保存待审批的具体动作、参数和运行关联；接受请求时读取这条记录并检查仍可审批，通过事务或原版等效机制保证只有一次能领取执行。拒绝、过期和撤权都不能继续调用。

暂停恢复时重新读身份、授权与已完成步骤；已完成的有副作用步骤不能因为重放时间线而再执行。技能文件仅提供执行说明，长期记忆是有作用域的内容，两者都不能自行扩大工具权限。

**停下来检查：** 有工具卡片却没有真实调用，查事件是否在适配器前被伪造完成；工具执行两次，查运行恢复与审批领取；取消不生效，查取消信号有没有传到正在等待的适配器。

## 7. `S9.5`：`MCP`、凭据、环境与沙箱

`MCP` 客户端连接外部工具，`MCP` 对外端点把本系统能力提供出去；两者方向不同。沙箱则提供隔离的运行环境，终端和浏览器连接属于真实远程会话。

原版入口：[MCP 服务接口](../../../frontend/src/api/mcp-service.ts)、[对外端点](../../../frontend/src/api/mcp-endpoint.ts)、[凭据](../../../frontend/src/api/credentialVault.ts)、[环境变量](../../../frontend/src/api/env-vars.ts)、[沙箱设置](../../../frontend/src/views/settings/SandboxSettings.vue)。

目标位置：`B/app/mcp/`、`B/app/integrations/sandbox/`、凭据与环境服务，以及 `F/src/views/toolbox/` 和相应设置面板。

1. **凭据与环境：** 先完成创建、脱敏读取、修改和删除，明确用户/空间/运行的可见范围；前端“未修改密钥”不得把掩码保存成新密钥。
2. **服务连接：** 复刻配置、连接检查、工具目录和启停；连接失败与没有工具要区分。每次实际调用仍重新检查授权。
3. **工具参数与输出：** 验证声明结构、输入限制、超时、取消和结果大小；工具输出是不可信内容，进入页面仍需安全渲染。
4. **对外端点：** 保留原版鉴权、能力范围和访问限制；用受限身份调用不允许的操作，确认后端拒绝。
5. **沙箱创建与生命周期：** 先实现配置、创建、状态、停止和释放，再接运行命令；记录所有者、运行标识与资源限制。
6. **终端：** 接入真实 `WebSocket` 或原版实际协议，处理连接、输入、输出、窗口变化、断线和过期；不能用静态终端文本冒充执行结果。
7. **浏览器与桌面：** 按原版连接协议接入，使用短期连接凭据；检查无权限连接、失效连接和取消后资源释放。
8. **文件与快照：** 校验沙箱路径、上传下载、产物引用及原版恢复能力；删除沙箱后不要留下仍可用的访问链接。

**检查例子：** 创建沙箱后连接终端，执行无害命令并看到实际输出；撤销访问权限后再次连接失败。客户端关闭或取消后，核对后端进程和配额是否释放。

**退出检查：** 密钥不出现在日志、构建产物或查询地址里；沙箱与主机边界、审批、超时、取消和清理均经过真实环境验证。

### 7.1 先接一项外部工具，再接一台沙箱

先在纸上画两个方向：本系统连接外部 `MCP` 服务，或外部客户端访问本系统端点。两边分别有客户端凭据与服务端授权，不能共用“连通即允许”的判断。

1. 凭据仓储先完成受控保存；读取接口仅返回允许展示的字段。在设置页面只改名称再保存，确认掩码没有覆盖原密钥。
2. `B/app/mcp/` 的外连入口读取授权后的连接配置，通过实际传输适配器获取工具目录。工具目录为空和连接失败用不同结果表达。
3. 从目录选一项只读工具，沿 `S9.4` 的参数校验、调用身份、超时与取消边界执行；把结果接到现有时间线，不另写聊天流。
4. 对外端点先接认证与能力范围检查，再开放一项已实现操作；用受限凭据请求范围外操作，确认没有执行副作用。
5. 在 `B/app/integrations/sandbox/` 先实现创建与查询状态，再由服务保存外部沙箱身份和本系统所有者的关联。远端创建成功、关联保存失败时，明确释放或可追查补偿。
6. 只有确认沙箱处于可连接状态后才签发对应短期连接凭据；前端用它接真实终端，执行无害测试命令，检查收到的是远端输出。
7. 终止沙箱后再次尝试旧连接和文件读取，确认失效；重复清理不会扣减两次配额或误删另一沙箱。

**停下来检查：** 工具可列但不可执行，查调用时的权限与参数；终端连接失败，先查后端关联和凭据，再查代理升级；页面关闭后资源持续占用，查远端生命周期而不是只看前端组件已卸载。

## 8. `S9.6`：自动化与外部渠道

自动化把“用户现在点一次”变成“在约定时间或事件下执行”。消息渠道把外部平台用户与系统内身份联系起来。它们都依赖已稳定的智能体执行和权限边界。

原版入口：[自动化页面](../../../frontend/src/views/automation/)、[自动化路由](../../../internal/router/routes_automation.go)、[消息渠道面板](../../../frontend/src/components/IMChannelPanel.vue)。

目标位置：`B/app/services/automations.py`、`B/app/integrations/channels/`、后台调度入口，及 `F/src/views/automation/` 和渠道面板。

1. **配置与手动执行：** 先保存一项任务并手动触发，执行参数、身份、结果和错误均可查询；同一界面区分任务定义与某次运行。
2. **定时触发：** 核对时区、表达式、下次执行时间、停用及错过执行的语义；前端预览时间与后端实际计划一致。
3. **重复与并发：** 为触发和运行建立稳定标识，按照原版规则处理重试、重叠运行与取消；重复回调不能造成重复副作用。
4. **运行历史：** 展示触发原因、开始结束、结果和错误；删除任务定义对历史的影响按原版记录，不默默清空审计证据。
5. **逐个渠道接入：** 为固定版本支持的每个平台登记认证、回调、身份映射和消息限制，先完成一条接收与回复，再补附件和历史等能力。
6. **回调保护：** 验证签名、时效和重复消息；未知来源拒绝处理。外部用户标识不能直接当内部管理员身份。
7. **发送失败：** 测试平台限流、超时、过长消息及撤销凭据，展示实际状态；重试不能重复发送已经确认成功的部分。

**验收时不要向真实业务群发送测试消息。** 使用明确授权的测试渠道和测试账号，记录本次触发对应的执行与外部消息标识。

**退出检查：** 时区、重复触发、停用、撤权、回调失败和发送重试都有证据；不能用一个渠道成功替代全部渠道兼容。

### 8.1 从手动运行演进到定时和回调

任务定义保存“以后怎样执行”，运行记录保存“这一次发生了什么”。一个定义可以产生多次运行，每次运行必须有独立可追踪身份。

1. 在 `automations.py` 先实现保存定义和受权读取，记录使用哪个智能体、以谁的身份执行；还不启动定时器。
2. 增加手动触发操作：从定义生成一次运行记录，再交给既有智能体执行入口。把运行身份串到任务、工具和结果，不复制执行循环。
3. 页面先显示定义列表与某次运行详情，刷新后从数据库读结果；执行失败仍保留运行记录。
4. 调度入口读取原版时间规则，计算下次触发并生成相同的运行输入。对同一计划时刻重复触发，按原版策略防止重复领取或错误重叠。
5. 停用定义后再次检查调度领取条件；已经执行的运行是否取消，按原版明确处理，不根据页面开关猜测。
6. 外部渠道先验证签名与消息时效，再将外部身份映射到允许的内部身份；由服务创建运行，不能把外部消息里的用户字段直接当可信管理员。
7. 回复按实际消息标识保存发送结果；模拟已发送但确认超时，验证重试使用平台支持的去重或查询机制，不能宣称网络失败就肯定没发送。

**停下来检查：** 预览时间正确却没有执行，查调度进程、时区及领取状态；收到重复回复，沿外部消息身份追到运行与发送记录；回调被拒绝先核对原始请求验证条件，不临时取消签名检查。

## 9. `S9.7`：组织、共享与系统管理全量

`S3` 已经完成基础租户隔离；本组补齐组织协作和管理界面。管理员界面和普通成员界面要分别验收。

原版入口：[组织页面](../../../frontend/src/views/organization/)、[成员设置](../../../frontend/src/views/settings/TenantMembers.vue)、[系统页面](../../../frontend/src/views/system/)、[系统接口](../../../frontend/src/api/system/)、[认证路由](../../../internal/router/routes_auth_tenant.go)。

目标位置：组织、成员、共享、认证与系统服务和仓储；前端对应 `views/organization/`、`views/system/` 与设置弹窗。复用已有认证依赖，不能各模块重新实现不同的权限判断。

1. **邀请与加入：** 实现发起、接受、拒绝、撤销和过期；邀请身份、目标组织和角色绑定，不能靠修改链接参数提高权限。
2. **角色和成员：** 用角色矩阵逐操作实现授权，补成员移除和角色变化后的缓存失效；检查运行中的请求是否仍能非法读取资源。
3. **资源共享：** 按原版区分知识库、智能体和其他资源的共享方式；共享撤销后，检索、引用、下载和执行入口都失效，不能只把列表项隐藏。
4. **`API Key`：** 补创建、展示时机、能力范围、轮换、撤销和审计；已有令牌不能在撤销后继续执行。公开文档只使用占位符。
5. **`OIDC`：** 实现原版身份提供方配置、跳转、回调和账号关联；校验状态与协议要求，测试失败回调、过期和已停用账户。
6. **初始化与模型目录：** 补初始化、供应商、调试和默认模型配置；已有用户数据不能被重复初始化覆盖。
7. **个人与空间设置：** 补资料、助手、历史、默认参数、检索和搜索服务、连接设置，明确每项作用域及保存后生效时间。
8. **基础设施设置：** 补存储、向量、解析器及原版支持的连接管理；修改连接不应默默丢失旧资源，涉及迁移时给出原版对应反馈。
9. **系统管理：** 补用户、管理员、全局配置、配额、平台密钥、队列、文档进度、诊断和审计。队列取消必须限制到当前允许范围。

**检查矩阵：** 系统管理员、空间管理员、普通成员、被移除成员和无登录用户，对每个管理接口分别验证允许与拒绝路径。

**退出检查：** 菜单、按钮和接口权限一致；设置弹窗没有重复挂载；退出与切空间后旧缓存不再显示敏感数据。

### 9.1 先打通一次共享，再验证撤回穿透所有入口

共享保存的是访问关系，资源本身仍有原归属。基础认证复用 `S3`，本组扩展“在当前身份下允许访问哪些资源”的规则。

1. 在成员与共享仓储中读取原版已有的授权关系，先准备拥有者甲、被共享者乙和无关用户丙三种身份。
2. 服务端共享操作先验证甲有授予权限，再保存原版允许的资源与接收方关系；禁止由接收方自行提高权限。
3. 读取详情和列表时接共享授权，确认乙可见且丙不可见；随后把相同可信范围接入检索目标解析。
4. 用乙完成一次搜索、问答和引用预览，再撤回共享。分别直接请求详情、检索、块、原件下载及执行入口，不仅观察列表变化。
5. 共享撤回后清理或隔离前端资源缓存；后台长任务再次访问资源时按原版规则重新检查，而不是永久使用投递时的授权快照。
6. 邀请与角色管理复用这套可信身份，但使用各自关系：邀请接受必须绑定目标身份、组织和角色；成员移除后再测试现有令牌的后续请求。

`API Key` 先做签发、能力范围和撤销，再接使用入口；`OIDC` 先接原版协议要求的登录往返状态验证，再做账号关联。二者共享授权服务，但验证凭据的方法不同，不能把浏览器回调参数直接转换成可信用户。

设置页先实现一项有明确作用域的设置，按“保存 → 重新读取 → 新请求使用 → 已运行任务行为”验证生效时间，再扩展同组字段。基础设施地址修改后还要验证旧资源能否读取，不能仅测新连接成功。

**停下来检查：** 撤回后列表消失但下载仍成功，查资源读取遗漏的授权；切空间后设置串用，查仓储条件和前端缓存键；重复初始化覆盖数据，查初始化入口是否验证现存状态。

## 10. `S9.8`：嵌入及其他运行入口

嵌入聊天是给外部访客使用的独立入口，不应该借用管理后台凭据。浏览器端通过也不能证明桌面或命令行已经兼容。

原版入口：[嵌入页面](../../../frontend/src/views/embed/)、[嵌入入口](../../../frontend/src/embed-main.ts)、[挂件脚本](../../../frontend/public/weknora-widget.js)、[集成界面](../../../frontend/src/views/integrations/)、[桌面绑定](../../../frontend/src/wailsjs/)。

目标位置：嵌入渠道服务、访客会话与令牌交换，`F/embed.html`、`F/src/embed-main.ts` 和嵌入组件；其他客户端保持各自目录和运行约定。

1. **渠道配置：** 先保存允许来源、绑定智能体、主题与原版访客策略；脱敏读取，不提供长期管理员令牌给宿主页。
2. **独立入口：** 配置打包、开发和生产路径回退，直接访问嵌入地址能进入正确应用，不误回主后台登录页。
3. **令牌交换：** 按原版协议获得访客会话，校验渠道和来源；过期、撤销或不允许来源时拒绝访问。
4. **宿主通信：** 校验 `postMessage` 的来源与消息结构；不接受任意窗口要求读取凭据或切换租户。
5. **完整聊天：** 复用已验证的消息、引用、附件和停止逻辑，同时保留访客权限；主应用退出或切租户不扩大访客权限。
6. **桌面运行时：** 列出本地文件、启动恢复、原生窗口、更新与离线相关行为，在支持的平台上逐项接入和测试。
7. **其他客户端：** 对命令行、浏览器扩展、外部接入说明及固定范围中的其他客户端建立清单，验证实际认证与调用，不以展示安装说明代替兼容性。

**成功与失败：** 在允许的独立宿主页完成聊天与引用，再用不允许的来源和过期凭据重复访问，必须拒绝。桌面测试需在真实桌面壳中记录结果。

**退出检查：** 各入口均有独立启动和权限证据；没有环境的入口留待验证，不能宣布整个产品完成。

### 10.1 给嵌入入口建立独立的身份与打包路径

嵌入页面是另一种客户端入口，不是把后台页面缩小。先复用已有聊天显示与状态处理，但分别提供访客凭据和允许资源范围。

1. 在渠道服务读取原版绑定智能体与允许来源配置；配置读取先脱敏，不把后台长期凭据交给宿主页。
2. 按原版令牌交换流程创建或恢复访客身份，后端校验渠道状态和来源策略。先以接口测试验证允许来源、拒绝来源、过期凭据三种结果。
3. 在 `F/embed.html` 与 `F/src/embed-main.ts` 接独立入口，只初始化访客需要的状态；主后台登录状态不得偷偷成为回退身份。
4. 复用 `S8` 聊天模块时显式提供访客请求客户端和上下文，防止调用默认后台认证对象；引用、附件和停止也走访客授权范围。
5. 配置构建入口后直接请求嵌入地址，再在独立测试宿主页加载。先验证空会话与发送，再测试刷新和停止。
6. `postMessage` 接收端先检查来源与消息结构，再执行允许的界面动作；未知消息不能切租户或读取凭据。
7. 最后补桌面与其他客户端。逐个列出原生文件、窗口、更新或认证所依赖的运行时接口，在真实壳内接入，不用网页成功推断原生接口可用。

**停下来检查：** 嵌入页刷新回后台，查产物与路径回退；访客能读管理资源，查默认身份回退；桌面文件选择没有响应，查原生绑定与平台分支，而不是改浏览器上传接口。

## 11. `S9.9`：跨页面体验收口

这一组贯穿前面每一页，最后再统一查漏。视觉一致的范围包括布局、文字、状态和交互，不只是颜色。

原版入口：[主题](../../../frontend/src/assets/theme/)、[语言](../../../frontend/src/i18n/)、[字体偏好](../../../frontend/src/composables/useFont.ts)、[全局命令面板](../../../frontend/src/components/GlobalCommandPalette.vue)。

2. **主题与字体：** 逐页检查明暗、跟随系统、偏好持久化及首屏；弹窗、菜单、代码块和预览器必须一起切换。
3. **键盘和焦点：** 用键盘完成登录、搜索、打开弹窗和关闭返回；焦点可见，关闭弹窗后回到合理位置。
4. **窄屏与长内容：** 对照原版布局、溢出、滚动区和输入框；长知识库名、长表格、长代码不能遮住操作。
5. **辅助交互：** 补新用户引导、快捷键、命令面板和原版动画；减少动画偏好存在时保留对应行为。
6. **统一截图：** 使用 `S0` 的同一浏览器、尺寸、数据、字体、语言和角色保存基线，逐项记录差异。不能用宽松阈值掩盖布局错误。
7. **样式收敛：** 新布局优先工具类，重复业务结构提取组件；保留必要主题和富文本样式，不为追求零样式破坏原版效果。

**退出检查：** 每个功能同时有行为和视觉结果；原版可操作的控件在新项目中可达、可见、可理解。

### 11.1 从一张真实页面修到全局一致

先选知识库列表作为第一张页面，准备正常、空、失败和弹窗状态；每种状态都由真实请求或可控失败产生，不能为了截图写死文案。
