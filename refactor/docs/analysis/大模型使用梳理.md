# WeKnora 大模型使用梳理

> 依据当前源码静态梳理，重点记录模型调用发生在哪里、由什么配置驱动，以及调用结果如何进入业务。文件路径均相对于项目根目录。

## 1. 总体结论

项目没有在业务代码中直接散落各家厂商 SDK，而是通过 `interfaces.ModelService` 统一按模型 ID 解析实例，再由五类能力接口发起调用：

| 能力 | 统一接口 | 主要用途 |
| --- | --- | --- |
| 对话模型 | `chat.Chat` | RAG 回答、智能体推理、摘要、标题、问题生成、知识图谱和 Wiki 生成 |
| 向量模型 | `embedding.Embedder` | 文档/图片向量化、查询向量、FAQ、记忆和知识库检索 |
| 重排模型 | `rerank.Reranker` | 对检索候选进行二次排序 |
| 视觉语言模型 | `vlm.VLM` | 图片理解、扫描件 OCR、图片上下文和多模态问答 |
| 语音模型 | `asr.ASR` | 语音输入转文字 |

统一入口见 `internal/types/interfaces/model.go`；实例创建和凭证解析主要在 `internal/application/service/model.go`。

调用外围还会叠加并发限制、`Langfuse` 追踪和 LLM 调试日志，相关实现位于 `internal/models/{chat,embedding,rerank,vlm,asr}`。

## 2. 用户问答与智能体链路

### 2.1 普通知识库问答

入口通常是会话或消息处理器，随后进入 `internal/application/service/chat_pipeline`：

1. `chat_pipeline/common.go` 根据 `ChatManage.ChatModelID` 获取对话模型并组装温度、上下文长度、思考模式、提示词缓存等参数。
2. `query_understand.go` 可调用对话模型做查询理解、改写、扩展；有图片时可按 `VLMModelID` 选择视觉模型，并支持回退到文本模型。
3. `knowledgebase_search.go` 使用知识库的 `EmbeddingModelID` 生成查询向量。
4. `chat_pipeline/rerank.go` 或 `knowledgebase_search_rerank.go` 使用 `RerankModelID` 对候选片段重排。
5. `chat_pipeline/chat_completion.go` 将系统提示词、历史、检索上下文和用户问题发送给 `chat.Chat.Chat`，生成最终回答。

核心调用证据：`internal/application/service/chat_pipeline/common.go`、`chat_completion.go`、`query_understand.go`、`rerank.go`、`internal/application/service/knowledgebase_search.go`。

### 2.2 ReAct/工具型智能体

`internal/agent` 是另一条对话运行时。内置智能体配置位于 `config/builtin_agents.yaml`，例如 `builtin-smart-reasoning` 启用知识搜索、文档读取、知识图谱查询和用户确认等工具。智能体循环最终仍通过 `ModelService.GetChatModel` 获取聊天模型；工具结果会被编码回上下文，再继续下一轮模型调用。

主要代码：`internal/application/service/agent_service.go`、`internal/agent/engine.go`、`internal/agent/act.go`、`internal/agent/observe.go`。

数据分析智能体会在 `chat_pipeline/data_analysis.go` 中使用聊天模型规划 SQL/统计分析，再执行工具并生成说明。

### 2.3 MCP 和外部调用

`internal/handler/mcp_usage_instructions.go` 可直接获取聊天模型生成 MCP 使用说明；MCP 暴露的问答接口也复用聊天模型。这里属于对外 API 入口，模型 ID 仍由租户模型配置决定。

## 3. 知识库导入、加工和索引

这是项目中模型调用最密集的后台链路。

### 3.1 文档向量化和检索索引

- `internal/application/service/knowledge_process.go`、`chunk.go`：文档分块后批量获取 `EmbeddingModel`，生成文本向量并写入检索库。
- `internal/application/service/knowledge_faq.go`、`knowledge_faq_import.go`：FAQ 导入、问题去重和 FAQ 向量化。
- `internal/application/service/tag.go`：标签或自动标签相关向量处理。
- `internal/application/service/knowledge_clone_move.go`、`knowledge_delete.go`：复制、迁移、删除时重建或清理向量。
- `internal/application/service/knowledgebase_search_image.go`、`image_multimodal.go`：启用图片向量时，对图片生成多模态向量。
- `internal/application/service/memory/vector.go`：长期记忆内容向量化。

向量模型支持远程兼容 API 和本地 `Ollama`；适配代码在 `internal/models/embedding` 及 `internal/models/api/*embeddings`。

### 3.2 摘要、知识库画像和自动问题

- `knowledge_process.go`：按知识内容调用聊天模型生成文档摘要、知识描述和结构化信息。
- `knowledgebase_profile.go`：调用 `SummaryModelID` 生成知识库描述和画像，失败时有重试及首段回退策略。
- `knowledge_process.go`、`chunk.go`：用问题生成模型为文档块生成 FAQ/检索问题，再用向量模型写入索引。
- `message_suggestion.go`：为会话生成后续问题建议。
- `session.go`、`session_agent_qa.go`：异步生成会话标题和会话摘要。

提示词模板集中在 `config/prompt_templates/`，配置加载和模板绑定在 `internal/config/config.go`。

### 3.3 图片、扫描件和多模态导入

- `internal/application/service/image_multimodal.go`：使用 `VLMModelID` 处理图片描述、OCR、图片上下文和多模态内容；支持失败回退。
- `internal/handler/session/image_upload.go`：会话图片上传后调用 VLM 生成图片说明。
- `internal/application/service/knowledge_process.go` 及文档解析器：扫描 PDF 或图片内容在必要时进入 VLM/OCR 流程。
- `internal/models/vlm/{remote_api.go,ollama.go}`：把图片和文本组装成多模态聊天请求。

图片向量与图片重排分别由 `embedding.EmbedImages` 和 `rerank.RerankImages` 处理，适配器见 `internal/models/embedding/protocol.go` 与 `internal/models/rerank/image.go`。

### 3.4 知识图谱和 Wiki

- `internal/application/service/graph.go`：调用聊天模型抽取实体、关系或图谱内容。
- `internal/application/service/wiki_ingest.go`、`wiki_ingest_batch.go`、`wiki_ingest_cite.go`、`wiki_ingest_dedup.go`、`wiki_ingest_taxonomy.go`：使用聊天模型进行页面生成、改写、引用筛选、实体/概念抽取、去重合并和目录规划；目录相似度还会使用向量模型。

这些调用有独立并发池、超时、重试、补全长度检测和截断续写逻辑，属于后台任务的主要模型成本来源。

## 4. 语音输入

语音模型不是文本大模型，但属于同一模型配置体系：

- `internal/handler/session/voice_input.go`：会话语音输入转写。
- `internal/application/service/session.go`、`session_knowledge_qa.go`：处理语音消息并进入问答。
- `internal/application/service/model.go` / `GetASRModel`：解析 ASR 模型。
- 统一接口为 `asr.ASR.Transcribe`，适配器在 `internal/models/asr`。

## 5. 模型、厂商和配置

### 5.1 模型生命周期

模型记录存储在模型仓储中。远程模型创建后直接置为可用，本地模型（主要是 `Ollama`）会异步下载，逻辑在 `internal/application/service/model.go`。模型类型、来源、默认模型和能力声明在 `internal/types/model.go`、`builtin_models_config.go` 及 `internal/models/catalog`。

### 5.2 厂商适配

厂商定义集中在 `internal/models/providers`，协议客户端集中在 `internal/models/api`。当前代码可见的适配类型包括 `OpenAI` 兼容聊天、`Ollama`、`LiteLLM`、`Google/Gemini`、`DashScope`、`Ark`、`Cohere`、`Pinecone`、`TEI`、腾讯 `LKEAP`、火山引擎等。具体可用模型以 `internal/models/catalog/data/*.json` 和租户模型配置为准。

### 5.3 环境配置

`.env.example` 中与模型直接相关的配置包括：

- `LLM_*`：内置聊天模型及 API 地址、密钥和供应商。
- `EMBEDDING_*`：向量模型配置。
- `RERANK_*`：重排模型配置。
- `OLLAMA_BASE_URL`：本地 `Ollama` 地址。
- `KNOWLEDGE_BASE_PROFILE_MAX_TOKENS`、问题生成和 VLM 补全预算。
- `WEKNORA_LLM_DEBUG_LOG`、`WEKNORA_LLM_STREAM_RAW_DUMP`：调试原始请求/响应。
- `Langfuse` 相关配置：追踪 `chat`、`embedding`、`rerank`、`VLM`、`ASR` 调用和 token 使用。

## 6. 统一调用链和横切能力

```text
HTTP / IM / 后台任务
        ↓
业务 Service 或 Agent Runtime
        ↓ 通过 ModelService + model ID
模型运行时解析（provider、协议、凭证、兼容参数）
        ↓
chat / embedding / rerank / vlm / asr 客户端
        ↓
并发限制、超时、重试、LLM 调试日志、Langfuse 追踪
        ↓
远程厂商 API 或本地 Ollama
```

模型调用的 token/耗时等使用信息会进入模型使用记录；相关代码见 `internal/application/repository/model_usage.go` 和各模型的 `langfuse_wrapper.go`。

## 7. 需要重点关注的影响面

1. 修改聊天模型解析或请求协议，会同时影响在线问答、智能体、摘要、标题、Wiki、图谱和问题生成。
2. 修改向量维度或 embedding 输入格式，会影响已有知识库索引；切换模型通常需要重新解析文档。
3. 修改重排阈值或返回结构，会影响普通检索、图片检索、智能体搜索和消息检索。
4. VLM 失败会影响扫描件、图片上下文和图片上传问答；需保留文本模型回退或可解释的失败状态。
5. 模型凭证由模型参数和租户配置共同解析，调试日志和 Langfuse 可能包含提示词、文档片段及模型输出，应按部署环境控制开关和保留周期。

## 8. 建议的后续维护入口

排查“某次请求为什么调用了模型”时，优先从业务入口的 `Get*Model` 调用开始，再沿 `internal/application/service/model.go` 进入对应适配器；排查模型成本时，优先查看 `knowledge_process.go`、`wiki_ingest*.go`、`chat_pipeline` 和 `image_multimodal.go`。
