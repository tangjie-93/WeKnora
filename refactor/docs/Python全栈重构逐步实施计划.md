# WeKnora Python 全栈从 0 到 1 逐步实施计划

## 1. 目标与范围

从工程初始化开始，自己逐步实现 `Python` 后端和独立前端，完成“注册登录 → 配置模型 → 建知识库 → 上传文档 → 检索 → 流式问答”的完整闭环，再扩展 `FAQ`、`Wiki`、`Agent` 和生产部署。

- 后端实现目录：`python/backend/`，使用 `FastAPI`。
- 前端实现目录：`python/frontend/`，使用 `Vue 3 + TypeScript + Vite`。
- `integration-web/` 不属于本计划范围：不读取其接口作为需求来源，不复用其页面、组件或鉴权逻辑，不修改、不构建，也不依赖它验收。
- “从零实现”指按依赖顺序亲自建立模块、契约、测试和页面，不以历史实现或已有完成率跳过步骤。
- 历史文档只作背景参考；完成状态以本轮实现和验收证据为准。
- 保留 `/api/v1` 路由前缀。已有数据库结构和契约保持不变；尚未定义的部分先设计并记录，再实现。旧系统迁移、Go/Python 双写对照、灰度切流及 Go 下线不属于本轮交付。
- 不删除或覆盖已有源码、数据库和未提交修改。若目标目录已有实现，先记录现状，在隔离工作树中开展重建；涉及覆盖或清理时单独确定处理范围。

## 2. 技术路线与执行规则

后端采用 `route → dependency → service → repository/integration` 分层；前端采用“页面 → 业务逻辑 → API 客户端”组织。路由不直接操作数据库，页面不自行拼装鉴权请求。

首个闭环使用 `SQLAlchemy 2 async + SQLite`、本地文件存储和确定性的假模型服务。使用 `pytest + pytest-asyncio` 验证后端；前端建立 `Vitest` 测试，并用 `Playwright` 验证关键浏览器流程。生产阶段再接入 `PostgreSQL`、`Redis + ARQ` 和对象存储。

每阶段必须交付：数据和接口契约、后端实现、对应前端页面、必要测试、可复现验收步骤。纯基础设施阶段可以只交付健康检查页或测试入口。以下文件路径是计划产物，不表示当前已经存在。

所有示例从本仓库 `refactor/` 目录起步，使用 `PowerShell`；进入前后端目录后分别运行对应命令。不要把本机绝对路径写入应用配置。

- [ ] 建立独立学习分支；如已有实现需要保留，使用隔离工作树，避免在原目录执行恢复或删除操作。
- [ ] 明确首版页面：注册登录、模型配置、知识库列表、知识库详情、检索、对话。
- [ ] 按用户操作定义接口：方法、路径、请求、响应、鉴权、分页、错误码及租户边界。
- [ ] 定义首批实体及关系：用户、租户、成员关系、模型、知识库；检查既有契约约束。

**验收：** 能说明每个页面的输入、输出及依赖；没有必须启动旧前端或旧后端才能完成的步骤。

## 4. 阶段 1：从零搭建前后端工程

**后端产物：** `pyproject.toml`、`app/main.py`、`app/core/`、`app/api/v1/router.py`、`tests/unit/test_health.py`。

- [ ] 创建虚拟环境，声明运行和开发依赖，配置 `Ruff` 与 `pytest`。
- [ ] 实现应用工厂、环境配置、日志、统一错误结构和请求标识。
- [ ] 实现 `GET /health`；生产环境缺少必要密钥时拒绝启动。

**前端产物：** `package.json`、`vite.config.ts`、`src/main.ts`、`src/App.vue`、`src/router/`、`src/services/`、`src/types/`、`src/pages/`。

- [ ] 初始化 `Vue 3 + TypeScript + Vite` 工程，添加路由和基础布局。
- [ ] 配置开发代理：前端 `5400`，后端 `8080`，请求使用相对路径 `/api/v1`。
- [ ] 建立统一请求客户端、错误提示和加载状态；实现服务状态页。
- [ ] 配置 `vue-tsc` 构建检查、`Vitest` 的 `test` 脚本及 `Playwright` 的 `test:e2e` 脚本。

**验收：** 页面可访问健康检查；断开后端后显示明确失败状态；前端构建和后端健康测试通过。

## 5. 阶段 2：数据库与迁移

**产物：** `app/core/database.py`、迁移目录、`app/domain/entities/`、`tests/contract/test_migrations.py`。

- [ ] 从实体关系设计建立用户、租户、成员关系和模型表，记录字段、索引及约束。
- [ ] 建立异步会话和事务边界；失败回滚，请求结束释放连接。
- [ ] 选择一种迁移机制并记录命令；新开发数据使用独立数据库。
- [ ] 测试空库初始化、重复运行、升级失败和事务回滚。
- [ ] 已有表结构受兼容约束时，新增迁移不得破坏原字段和数据。

**验收：** 新建测试库可以完整初始化；迁移失败会停止流程，不能静默跳过。

## 6. 阶段 3：注册登录与租户隔离

**后端：** 鉴权路由、用户与租户服务、密码哈希、访问令牌、刷新令牌及会话失效机制。

**前端：** 注册页、登录页、当前用户状态、路由守卫、退出操作和租户选择。

- [ ] 定义并实现注册、登录、刷新、退出、当前用户接口。
- [ ] 明确令牌存储和传输方式；不在 URL、源码和日志中放置凭据。
- [ ] 服务端校验用户与租户成员关系，所有租户数据查询包含租户条件。
- [ ] 请求客户端统一处理未登录、过期和无权限，避免刷新重试死循环。
- [ ] 测试错误密码、重复注册、令牌过期、重复刷新及跨租户访问。

**验收：** 浏览器完成注册、登录、刷新页面、退出；退出后受保护页面不可访问，跨租户请求被拒绝。

## 7. 阶段 4：模型配置与模型网关

**后端：** 模型实体、配置接口、连通性检查和模型调用客户端。

**前端：** 模型列表、新增编辑表单、默认模型选择和连接测试反馈。

- [ ] 先实现本地假模型服务，提供确定性对话及向量结果。
- [ ] 实现模型配置校验；响应和日志不返回完整密钥。
- [ ] 支持模型超时、无效响应、连接失败及类型不匹配的错误反馈。
- [ ] 自动化测试默认使用假模型；真实模型测试单独开启并记录费用风险。

**验收：** 页面创建并测试模型；失败原因可见；刷新后配置保留，密钥不可从列表响应读取。

## 8. 阶段 5：知识库管理

**后端：** 知识库实体、服务、仓储及增删改查接口。

**前端：** 知识库列表、创建表单、详情页、编辑和删除确认。

- [ ] 实现基础分页、空状态、重复提交防护和错误状态。
- [ ] 校验模型关联及租户归属。
- [ ] 明确知识库删除对文档、文件、任务和向量的影响，避免孤立数据。
- [ ] 测试创建、查询、修改、删除及越权；标签和文件夹在主流程通过后补充。

**验收：** 登录后能创建并重新打开知识库；其他租户不能读取或修改。

## 9. 阶段 6：上传、解析与入库

**后端：** 文件存储、上传接口、解析器、分块逻辑和任务状态查询。

**前端：** 文件选择、上传进度、文档列表、解析状态、失败重试和删除。

- [ ] 先支持文本文件，再逐步增加 `PDF`、`DOCX`；不支持的类型明确拒绝。
- [ ] 限制大小，校验实际类型，防止路径穿越和文件名冲突。
- [ ] 定义 `queued → running → succeeded/failed` 状态，保存失败原因。
- [ ] 文档解析、分块和向量写入可重试，重复处理不产生重复数据。
- [ ] 明确进程重启后的任务处理方式，不把内存任务视为可靠持久化队列。

**验收：** 上传后可看到可查询的文档和分块；解析失败、重复上传、删除中断均有测试及可见反馈。

## 10. 阶段 7：检索

**后端：** 关键词检索、向量检索、排序融合与结果接口。

**前端：** 检索输入、数量设置、结果列表、来源和空结果状态。

- [ ] 根据本轮契约确定请求字段；前后端统一含义，不为旧集成页增加适配层。
- [ ] 使用固定文档和向量测试排序、去重、数量上限和租户过滤。
- [ ] 处理空查询、无结果、模型失败及向量维度不匹配。
- [ ] 检索结果返回正文、分数、文档标识及分块位置。

**验收：** 上传的文档可以被检索，引用可追溯；跨知识库和跨租户范围受到约束。

## 11. 阶段 8：会话与流式问答

**后端：** 会话、消息持久化、检索增强问答和 `SSE` 流。

**前端：** 会话列表、消息历史、输入框、增量回答、引用、停止生成和重试。

- [ ] 定义 `answer`、`references`、`complete`、`error` 的事件结构并写入契约。
- [ ] 先保存用户消息；流结束保存回答，异常保存已生成内容和失败状态。
- [ ] 客户端解析跨网络块事件，处理取消、断流、重复发送和页面离开。
- [ ] 完成事件与错误事件互斥；服务端收到取消后释放模型连接。
- [ ] 测试消息刷新后恢复、空回答、上游超时和引用权限。

**验收：** 浏览器独立完成“登录 → 建库 → 上传 → 检索 → 问答”；刷新后会话、消息和引用正确。这是首个完整版本的交付门槛。

## 12. 阶段 9：扩展功能

主闭环验收通过后，逐项设计契约、实现后端与页面，不同时展开全部扩展。

| 顺序 | 功能 | 前后端交付 | 核心验收 |
|---|---|---|---|
| 1 | 标签与文件夹 | 管理接口、筛选及移动交互 | 移动和删除不丢失文档 |
| 2 | `FAQ` | 问答条目管理、搜索、批量操作 | 批量操作范围及租户权限正确 |
| 3 | `Wiki` | 页面编辑、版本、回滚、图谱 | 冲突返回 `409`，回滚生成新版本 |
| 4 | `Agent` | 配置页、执行循环、工具事件展示 | 限制迭代次数，支持超时及取消 |
| 5 | `MCP` | 服务配置、连接检查、工具审批页 | 拒绝或过期审批不能执行，重复审批幂等 |
| 6 | 组织与嵌入 | 成员管理、邀请、独立访客入口 | 邀请过期生效，访客凭据与主应用隔离 |

嵌入入口由新前端独立实现；验证宿主消息来源，不内置默认账号和长期令牌。

- [ ] 验证数据库备份恢复、版本升级和部署回退。

**验收：** 在干净环境按照文档启动完整系统，通过浏览器主流程和真实依赖测试；无需旧系统参与。

## 14. 每阶段验证与提交

1. 记录当前目标、依赖、接口和验收标准。
2. 为非平凡逻辑与已知失败边界写最小有效测试。
3. 实现后端和前端，先跑相关测试，再执行阶段检查。
4. 在浏览器操作真实页面，核对请求、错误提示和持久化结果。
5. 更新进度、证据、已知限制及下一步。
6. 检查差异，仅提交当前任务文件；推送按当次授权执行。

后端示例（先从 `refactor/` 进入目录，虚拟环境和依赖已初始化）：

```powershell
cd python/backend
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check app tests
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8080
```

前端示例（另开终端，从 `refactor/` 进入；测试脚本须在阶段 1 创建）：

```powershell
cd python/frontend
npm install
npm run test -- --run
npm run build
npm run test:e2e
```

浏览器测试须按配置启动前后端及假模型服务，并使用独立测试数据库。阶段报告记录实际命令、结果和证据路径；不能将计划中的测试标记为已通过。

## 15. 建议学习节奏

- 第一轮：完成阶段 `0–2`，理解工程、请求生命周期和数据持久化。
- 第二轮：完成阶段 `3–5`，打通登录、模型配置和知识库页面。
- 第三轮：完成阶段 `6–8`，打通上传、检索及流式问答。
- 后续：按需要逐项完成阶段 `9–10`。

每轮用验收结果决定是否进入下一轮，不要求一天完成一个复杂业务域。遇到失败先记录和定位，避免通过复制历史模块跳过理解过程。

## 16. 完成标准与暂缓事项

每阶段报告回答：新增了哪些页面和接口、成功与失败路径如何验证、租户隔离是否成立、数据是否落盘、仍有哪些限制、下一阶段依赖是否满足。

首版暂缓全部历史接口覆盖、旧系统切流、微服务、桌面端、多厂商全量适配和复杂图谱。首版必须保留鉴权、输入校验、错误处理、数据保护、可访问交互及取消清理；不能为缩短实现而省略。
