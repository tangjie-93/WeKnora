# WeKnora 重构文档

这里的文档服务于四类工作：运行和集成 `WeKnora`、了解当前实现、推进 Python 后端迁移、学习前端实现。先按目标选择入口，避免把架构指南、进度台账和使用说明混在一起阅读。

## 1. 按目标阅读

### 1.1 先运行或使用 `WeKnora`

1. [本地部署与使用说明](./operations/WeKnora本地部署与使用说明.md)：本地部署、模型配置、首次使用和常见排错。
2. [外部项目集成方案](./operations/WeKnora外部项目集成方案.md)：鉴权、建库、上传、检索和对话的调用顺序。

### 1.2 了解当前实现

1. [前后端实现清单](./progress/前后端实现清单.md)：前端、Python 后端和前后端联通状态的当前快照。
2. [大模型使用梳理](./analysis/大模型使用梳理.md)：模型在问答、Agent、知识库加工、语音和外部调用中的使用位置。
3. [前端知识点与可迁移能力梳理](./analysis/frontend-knowledge-map.md)：前端值得复用的实现模式和迁移优先级。

### 1.3 参与 Python 后端重构

1. [Python 全栈重构逐步实施计划](./Python全栈重构逐步实施计划.md)：按任务、文件、测试和验收标准逐步实现。
2. [Python 后端技术架构与迁移指南](./architecture/Python后端技术架构与从0到1迁移指南.md)：目标分层、阶段边界和实施顺序。
3. [Python 后端重构进度管理](./progress/Python后端重构进度管理.md)：阶段状态、验收证据和当前下一步；这是迁移进度的唯一台账。
4. [前后端实现清单](./progress/前后端实现清单.md)：核对前端真实调用和联通缺口。
5. `refactor/python/backend/tests/contract/route_matrix.md`：接口覆盖的机器生成结果。

### 1.4 学习前端实现

2. [前端知识点与可迁移能力梳理](./analysis/frontend-knowledge-map.md)：适合快速浏览关键设计点。

## 3. 更新规则

1. 代码或接口变化后，先更新对应的源码证据和测试，再更新文档中的数字与状态。
2. `前后端实现清单`记录“当前是什么”；`Python 后端重构进度管理`记录“迁移到哪里”。同一指标不在两处手工维护不同数字。
3. 阶段验收以 `refactor/python/backend/tests/contract/stage_report_*.md` 和对应测试为证据；只有源码存在时，状态写为“部分完成”。
4. 路由或进度数字优先通过脚本生成：

   ```powershell
   py -3.13 scripts/generate_route_matrix.py
   py -3.13 scripts/update_refactor_progress.py
   ```

5. 新增文档先判断是否能补充现有文档；只有读者、用途或生命周期不同，才新增文件。
