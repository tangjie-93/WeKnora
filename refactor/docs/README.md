## 2. 从零实施的统一顺序

`S0` 固定基线 → `S1` 工程骨架 → `S2` 数据库 → `S3` 身份与租户 → `S4` 模型 → `S5` 知识库 → `S6` 上传解析 → `S7` 检索证据 → `S8` 流式问答 → `S9` 完整功能 → `S10` 部署验收。

每阶段同时推进后端、前端与验收。前端保留原版 `TDesign`、主题和素材，用 `Tailwind CSS ^4.3.3` 减少布局样式；功能和视觉都以固定原版为参照。

## 3. 文档职责与当前状态

集中教程讲“接下来怎样实现”；全链路资料讲“原版如何运行”；使用说明讲“如何启动或接入”。历史记录保留当时背景，不作为当前完成状态。

早期整理时 `refactor/python/` 尚不存在，这是历史背景，不是当前状态；现有双端工程已落地健康与导航切片。当前仅实现 `S2.2` 显式本地 `SQLite` 连接检查子项，首轮 `FAILED/P1-01` 经窄修后复审 `PASSED`，`TASK-04` 独立新增 `117` 项、全套 `128` 项通过；业务数据、`schema`/迁移、`ORM` 未实现，整个 `S2` 未验收。实际状态统一见[进度与验收记录](./从0到1重构WeKnora/13-进度与验收记录.md)，命令合同见[后端说明](../python/backend/README.md)。旧索引中的接口覆盖报告及生成脚本不作为可执行入口。

## 4. 更新规则

1. 新增业务前记录原版行为、接口和数据要求；实现后补真实测试与视觉证据。
2. 修改阶段顺序时同时更新集中目录和总路线，不再新增另一套编号。
3. 移动文档时更新入站链接；原版源码链接以实际存在的文件为准。
4. 未执行的命令、未建立的工程、待创建的脚本必须明确标注，不能写成已经通过。
5. 不把凭据、本地数据库或私人业务资料写入文档和测试报告。
